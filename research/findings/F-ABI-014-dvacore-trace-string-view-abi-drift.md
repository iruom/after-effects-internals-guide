# F-ABI-014 — dvacore trace category APIs changed C++ ABI between 25.6 and 26.3

`dvacore.dll` keeps the same trace concepts across both installed versions, but the decorated exports for category-level trace volume access changed ABI.

- AE 25.6: `GetTraceVolume` / `SetTraceVolume` take `std::string_view` by const reference.
- AE 26.3: the same operations take `std::string_view` by value.
- `GetMasterTraceHandler`, `InstallMasterTraceHandler`, `RemoveMasterTraceHandler`, `MasterTraceToStdErr`, and master-volume accessors keep the same non-string-view decorated form across the two binaries.

The machine inventory is `datasets/ae-dvacore-trace-abi-lineage.csv`, generated by `probes/process-tools/inventory_dvacore_trace_abi.py`.

## Consequence
Private/runtime C++ exports cannot be treated as source-compatible or ABI-stable merely because the semantic function name survives. A probe that imports only one decorated `GetTraceVolume` signature is version-fragile.

AEIG's trace wrapper therefore resolves both decorated signatures at runtime and represents the MSVC `string_view` payload as a two-field pointer/length ABI object while keeping the Artie sample on C++14.

## Experimental check
The wrapper was standalone-smoke-tested against both installed `dvacore.dll` versions; both runs exited 0 and completed handler/stderr restoration. Category mutation itself remains a full-host question because standalone providers retain volume 5.
