# Modern 3D uses GUID-keyed resource caches below the Artisan boundary

`BEE.dll` exports distinct modern 3D resource types for model, mesh, texture, model-info, overridden-model, and basic ASM material data. Each family is paired with `BEE_AE3D_ResourceGuard`, `Cache(...)`, `FindCached(...)`, `IsCached`, `GetGuid`, release/reset helpers, and `AE3D::CacheFlags`.

Examples include `BEE_AE3D_MeshResource::Cache(Guid, ...)`, `BEE_AE3D_TextureResource::Cache(Guid, ..., AEGP_PixelFormat_v1)`, `BEE_AE3D_BasicModelResource::Cache(Guid, BasicModel)`, and `BEE_AE3D_BasicASMMaterialResource::Cache(Guid, BasicASMProperties)`.

This is direct evidence that modern 3D has intermediate resource identity/residency below final frame caching.
## Integration boundary
Installed `Advanced3D.aex` depends directly on `PF.dll`, `BEE.dll`, and `PR.dll`. Its imports include `BEE_GetArtisanRenderOptions`, `BEE_ArtisanLayerCapsuleParamsHelper`, and `PR_ExtractRenderRefcon`, which ties the modern renderer to the long-lived Artisan render-context boundary while still using BEE-managed resources.

BEE simultaneously exposes parametric mesh layers/options, camera/light layers and stream groups, material streams, Substance material integration, and GUID-bearing AE3D resources. The strongest model is therefore:
`TDB/BEE scene streams -> AE3D resource materialization/cache -> Artisan/renderer context -> texture/layer results -> BEE/RG compositing`.

## Important non-equivalence
Resource GUIDs are not proven to equal BEE frame Render GUIDs. A mesh/material/texture can be reusable while a final composition frame is invalid, and vice versa. Treat scene-resource identity, render-request identity, and final-frame residency as separate coordinates.
